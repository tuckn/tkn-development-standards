# Markdown記述規約

見出し・リスト・太字の使い分けと、リストの入れ子のインデントを定めます。
人と生成AIが、リポジトリの文書やエディターで書くノートの構造を、同じ考え方で組み立てるための共通規約です。

## 1. 位置付けと適用範囲

本書は、人と生成AIが書くMarkdown（README・CHANGELOG・docs、Obsidianなどのエディターで書くノート）に、実装言語を問わず適用します。
記法そのものは、CommonMarkとGitHub Flavored Markdown（GFM）に従います。
CommonMark・GFM・Obsidianが定めているのは記法で、見出しにするかリストにするかといった使い分けは定めていません。
本書は、その使い分けを、markdownlintのルールと、主なパーサー・エディターの動き（6章）を根拠に定めます。
リストの入れ子のインデント（5章）は、CommonMarkの規則をそのまま使います。

READMEの章構成と見出しの名前の付け方は [CLIリポジトリREADME執筆規約](readme-writing.md) の3.5に、Markdownのソースの読みやすさ（空行、1文1行など）は同じく5.3に従います。

## 2. 見出し・リスト・太字の役割

| 書き方 | 示すもの | エディターで畳める | アウトラインに出る・リンクの先になる |
| --- | --- | --- | --- |
| 見出し（`#`〜`######`） | 文書の階層（節） | はい | はい |
| リスト（入れ子を含む） | 文書の階層（項目と、その下の項目） | はい | いいえ |
| 太字 | 文の中の要点（強調） | いいえ | いいえ |

- 見出しとリストは、どちらも文書の階層を示します。
- Obsidianなどのエディターは、見出しの節も、子の項目を持つリストの項目も畳めます。
- 見出しは、さらにアウトライン（目次）に出て、リンクの先になります（GitHubの見出しのアンカー、Obsidianの `[[ノート#見出し]]`）。
- 太字は強調で、階層を示しません。

## 3. 見出しにするかを決める

- 「そこへリンクしたいか」「アウトラインからそこへ飛びたいか」を目安にします。
  どちらかに当たる節を、見出しにします。
- どちらにも当たらないもの（数個の項目をまとめる分類の印など）は、見出しにせず、リストの項目にして、中身をその下に入れ子にします。

  ```markdown
  - **Background**:
    - <内容>
    - <内容>
  ```

- 小さなまとまりまで見出しにすると、中身より見出しのほうが重くなります。
  アウトラインも長くなり、探したい節が見つけにくくなります。

## 4. 太字の1行を見出しの代わりにしない

- 節を分けるのに、太字だけの1行を使いません。
  ツールが文書の構造を読み取れなくなるためです（markdownlintのMD036）。
  見出しにするか、3章のようにリストの項目にします。
- 太字のラベルの次の行からリストを書く形（`**Background**:` の直後に `- …`）も使いません。
  - 空行がないと、パーサーによってはリストとして読まれません。
    pandocのMarkdownは、ラベルとリストを1つの段落として読みます（6章）。
    kramdownなども、前後に空行のないリストを読みません（markdownlintのMD032）。
  - 空行を入れると、どの項目がどのラベルの下かは並び順でしか分からず、エディターでラベルごとに畳めません。
- MD036は、末尾が `:` などの句読点で終わる段落を、既定で対象外にします。
  lintを通っても、太字の1行が見出しの代わりになっていれば、この章に当たります。

## 5. リストの入れ子のインデント

- 入れ子にする行は、親の項目の本文が始まる桁に揃えます（2026-11-19に決めました）。
  幅は固定せず、親のマーカーの幅で決まります。
  CommonMarkの規則と同じです。

  | 親のマーカー | 子のインデント |
  | --- | --- |
  | `- `（箇条書き） | スペース2つ |
  | `1. `（番号付き、1桁） | スペース3つ |
  | `10. `（番号付き、2桁） | スペース4つ |

  ```markdown
  - 親
    - 子
      - 孫

  1. 親
     - 子
  ```

- マーカーの後ろのスペースは1つにします。
- インデントにはスペースを使い、タブを使いません。
  CommonMarkは、タブを4桁ごとのタブ位置として扱います。
  スペースと混ぜると、桁がずれます。
- 番号付きの項目の下を、スペース2つで字下げしません。
  本文が始まる桁（`1. ` ならスペース3つ分）に届かず、CommonMarkでは子の項目になりません。
- 項目の中に置く段落・コードブロック・表も、同じ桁に揃えます。
- 幅を4つに固定しないのは、次の理由です。
  - CommonMarkとGFMが、幅の固定をやめて、この規則にしています。
  - 等幅フォントで編集すると、4つは深い入れ子で横に長くなります。
  - markdownlintの既定（MD007）と、AIエージェントが書く幅が、箇条書きで2つです。
- Obsidianは、Tabキーでスペース4つを入れます（6章）。
  この決まりに合わせる手段は、まだ決めていません。
  それまでは、Tabキーで入った幅を手で直します。

## 6. 根拠

見出し・リスト・太字（2〜4章）は、2026-11-13に確かめました。

- markdownlintの [MD036（no-emphasis-as-heading）](https://github.com/DavidAnson/markdownlint/blob/main/doc/md036.md)：節を分けるのに強調を使うと、ツールが文書の構造を推し量れない、としています。
  既定の `punctuation` は `.,;:!?。，；：！？` です。
- markdownlintの [MD032（blanks-around-lists）](https://github.com/DavidAnson/markdownlint/blob/main/doc/md032.md)：kramdownなど一部のパーサーは、前後に空行のないリストを読まない、としています。
- pandoc 3.9.0.2：`**Background**:` の次の行に `- item one` を書いた入力は、`-f markdown` では `<p><strong>Background</strong>: - item one …</p>` という1つの段落になり、`-f gfm` ではリストになりました。
  pandocのMarkdownでは、拡張 `lists_without_preceding_blankline` が既定で無効です。
- Obsidianのヘルプ [Folding](https://obsidian.md/help/Editing+and+formatting/Folding)：見出しと、字下げしたリストを畳めます。
- [Google Markdown style guide](https://google.github.io/styleguide/docguide/style.html)：太字を見出しの代わりにすることには触れていません。
  リストと小見出しで同じ情報を示せることがある、としています。

リストの入れ子のインデント（5章）は、2026-11-19に確かめました。

- [CommonMark Spec 0.31.2](https://spec.commonmark.org/0.31.2/#list-items) の「List items」：幅Wのマーカーの後ろにN個（1〜4）のスペースがあるとき、項目の中身はW+N個のスペースで字下げします。
  同じ節の「Motivation」は、元のMarkdownの説明から読み取れる4スペースの規則を、明快だが不自然で、初心者がよくつまずく、としています。
  人は項目の本文をひとかたまりと見て、マーカーの分だけ字下げする、という考えで今の規則を選んでいます。
- 同じ仕様の「Tabs」：スペースがブロックの構造を決める場面では、タブを4桁のタブ位置として扱います。
- markdownlintの [MD007（ul-indent）](https://github.com/DavidAnson/markdownlint/blob/main/doc/md007.md)：`indent` の既定は2です。
  親がすべて箇条書きのリストだけを対象にします。
  4つにすると、コードブロックと揃い、エディターが実装しやすいこと、4つを求めるパーサーがあることにも触れています。
- [Google Markdown style guide](https://google.github.io/styleguide/docguide/style.html)：入れ子のリストは、箇条書きも番号付きも4つです。
  マーカーの後ろを、番号付きは2つ、箇条書きは3つ空けて、本文をスペース4つ分の位置に揃えます。
  本書は、これを採っていません。
- Obsidian 1.15.1：「タブでインデント」を切り、インデントの幅の設定（`tabSize`）を2にしていても、Tabキーはスペース4つを入れました。
  フォーラムにも [同じ報告](https://forum.obsidian.md/t/editor-ignores-tab-size-2-setting-for-nested-lists-always-inserts-4-spaces/111415) があり、この設定はタブ文字の表示幅（Indent visual width）だ、という返信が付いています。
  公式の文書では確かめていません。
