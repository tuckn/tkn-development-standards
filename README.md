# Tkn Development Standards — CLI開発・文書作成・YAML記述の共通規約

人と生成AIが、CLIの開発・文書作成・YAML記述に共通して使う規約です。
README・CHANGELOG・詳細文書を、人が実装の成果と根拠を確認できる入口として整えます。
主な読者が日本語話者のため、本リポジトリの文書は日本語で管理します。

## 作業に応じて読む

| 作業 | 文書 | 適用範囲 |
| --- | --- | --- |
| スクリプト・CLIを新しく作るときに、書く言語を選ぶ | [スクリプトの言語の選び方](docs/script-language-selection.md) | 動く場所、既存の共通処理、Pythonの順で選ぶ考え方と、PowerShell・Node.js・BAT・CMD・AutoHotkey・VBA・WSHを使う条件 |
| Python CLIの新設・大幅な再設計 | [Python CLI開発基本方針](docs/python-cli-development.md) | Windowsを主対象とするPython・uv・src構成、設定、配布、安全性、検証 |
| README・CHANGELOG・docsの作成や改訂 | [CLIリポジトリREADME執筆規約](docs/readme-writing.md) | 実装言語を問わない情報配置、説明、事実確認、更新手順 |
| CHANGELOG.mdを置く・書く | [CHANGELOG規約](docs/changelog-writing.md) | Gitで管理するすべてのリポジトリ（コード、制作フォルダ、文書・ノート）。置く条件、作るとき、書くこと、版・日付の節の書き方 |
| Markdownの文書・ノートの構造を決める | [Markdown記述規約](docs/markdown-style.md) | 実装言語を問わない見出し・リスト・太字の使い分け。見出しにするかの目安と、太字の1行を見出しの代わりにしないこと |
| YAML設定・Frontmatter・文書内YAML例の作成や修正 | [YAML記述規約](docs/yaml-style.md) | 実装言語を問わない日時、引用符、型、識別子、パス、移行時の情報保持 |
| テキストファイルの作成・編集、`.gitattributes` の設定 | [改行コード・文字コード規約](docs/line-endings-and-encoding.md) | 実装言語を問わないLF・UTF-8の基本と、Windows専用の形式（BAT・CMD、PowerShell、AutoHotkey、WSH、VBA）のCRLF・文字コード |
| 短い紹介動画を、HTMLとコードで描いて作る | [コードで描くモーショングラフィックス動画の制作ガイドライン](docs/motion-graphics-video-production.md) | 時刻だけで描く作り方、関門と確かめ方、生成AIの推論が走るところ、見た目、読む時間、書き出し、音、参照の動画の渡し方。実例1本で確かめた目安 |

README・YAML・改行コードの規約を使うために、Pythonの規約全体を採用する必要はありません。
どの言語で書くかは、[スクリプトの言語の選び方](docs/script-language-selection.md)で選びます。
Node.jsなど他の実行環境の規約は、具体的な共通要件がまとまった時点で追加します。

## 対象プロジェクトへの適用

1. 作業に該当する文書を選び、対象と適用条件を確認します。
2. 対象リポジトリの指示・仕様・既存利用者への影響を確認します。個別依頼を優先し、例外と理由を記録します。
3. 共通規約をそのまま複製せず、対象プロジェクトには参照先と固有の追加条件を置きます。
4. 生成AIには実際に読める文書を渡します。URLを記載しただけで読めたとみなさず、取得できなければその旨を示し、添付やcheckoutで必要な内容を提供します。
5. 再現性が必要な作業では、参照したcommitやreleaseを記録します。作業結果には確認内容と未確認事項を残します。

このリポジトリが共通規約の正本です。作者（Tuckn）のCLI prefix・設定namespace・公開済みの参考リポジトリは、各規約の該当箇所に適用例として記載します。
個人の作業環境のパス、実データ、特定Vaultのschema・移行規則、非公開の資料は各環境側で管理します。これらを読まなくても、本リポジトリの規約を利用できる状態を保ちます。

## 文書を改訂する

- 詳細文書は原則として `docs/` 直下へ、内容の分かるkebab-caseの名前で置きます。分類だけのためにフォルダを増やしません。
- 共通要件と対象固有の追加条件を分け、同じ詳細を複数の正本へ複製しません。
- 移動・改名時はREADMEと文書間リンクを更新します。必要な情報、互換性、保護条件を失わないか確認します。
- 実装やツールの現行動作を保証する記述を追加する場合は、確認した対象・版・根拠を示します。
- 利用者に影響する改訂を [CHANGELOG](CHANGELOG.md) に記録します。
- 公開対象の差分に個人の実パス、適用例として示す以外の個人の識別情報、秘密情報、実データ、非公開資料への依存が含まれないか確認します。
- 変更後は相対リンク、文書の適用範囲、サンプルと規約の整合を確認します。公開前には追跡ファイルとGit履歴も確認します。

## 現在の状態

共通規約6文書と、スクリプトの言語の選び方の指針1文書、動画の制作のガイドライン1文書を収録した初期版です。実装言語をまたいで利用できるREADME・YAML・改行コードの規約と、Python固有の開発規約を分けています。動画の制作のガイドラインは、規約ではなく、実例から得た目安として置いています。
GitHubへの文書の反映は別途行います。配布ライセンスは未設定です。
